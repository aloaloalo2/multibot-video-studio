# Створення ролика з коротким контекстом

Студія передає Claude Code чинний план, готові кадри й файли сцен однією картою роботи. Режисер визначає смислові кадри після озвучки. Аніматор реалізує ці кадри, зберігаючи їхні номери й таймінги. Експорт відтворює той самий код. Повторне розбиття сценарію під час анімації не потрібне.

## Передача між етапами

- `python3 tools/studio.py work P` або `GET /api/projects/<id>/work?format=text` показує короткий актуальний список кадрів, стан і файли сцен.
- Перед запуском production студія записує `production-context.json` і компактний `production-context.txt` у власну папку даних проєкту. Це похідний індекс. Редаговані джерела залишаються у плані студії та `story/shots.json`.
- Розбіжність сценарію або меж кадрів із `story/studio_frames.json` виявляється до звернення до моделі.
- Повний текст і задум поточного кадру читайте через `studio.py plan P --frames N-M`. Весь сценарій і документи інших випусків для точкової правки не потрібні.
- Виправлення відкриває нову коротку сесію Claude. Продовження після паузи або ліміту зберігає попередню сесію. Зроблені сцени й матеріали залишаються на диску в обох випадках.
- Кожен запуск правок має окремий журнал, щоб його витрати не затерли попередній запуск.

## Одна перевірка зображень

`frame_review.py sheets` створює по три стоп-кадри нових або змінених кадрів. Цей аркуш використовується для перевірки змісту, композиції, поз і якості. Другий суцільний `render.mjs --sheet` для тієї самої версії не потрібен.

Перевірка зберігає відбитки вмісту файлів. Незмінений кадр використовує готові зображення. Зміна шоту враховує також сусідні стики та імпортовані модулі. Зміна спільного рушія, декорації, стилю чи асетів вимагає нової перевірки залежних кадрів. `status` перевіряє актуальність кожного кадру, навіть після роботи лише над вибраним діапазоном. `sheets --all` примусово оновлює всі стоп-кадри.

Початковий перегляд усіх нових кадрів залишається обов'язковим. Після правки переглядайте змінені кадри та їхні стики. Перевірки руху й продуктивності виконуйте для відповідних діапазонів. Повний рендер запускає користувач.

Особливо перевіряйте контури персонажів: засильне контрове світло може виглядати як сторонні смужки чи друга кінцівка. Порівнюйте однаковий момент до й після правки та ще декілька поз.

## Асети

1. Перевірте вже прикріплені предмети та `assets/library-picks.json`.
2. Один точний пошук `library.py search <слова> --limit 6 --sheet build/candidates.png`. Без `--sheet` читаються лише назви й описи, картинки не відкриваються.
3. Перегляньте один невеликий аркуш. Відповідний предмет прикріпіть через `library.py use`. Назва та відбиток зберігаються для повторного використання.
4. Якщо відповідного предмета немає, підготуйте промпт і згенеруйте потрібні предмети одним аркушем. Не повертайтеся до пошуку тих самих предметів по колу.

Пошук у бібліотеці локальний. Перегляд кандидатів витрачає контекст моделі, генерація може мати окрему вартість і час очікування. Точний розмір економії оцінюйте за наступними справжніми звітами `studio.py spend P --all`; тест зміни процесу не запускає платного створення ролика.
