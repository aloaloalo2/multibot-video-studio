## Native timeline regression checks

Visual clip times must quantize their absolute start and end with the same deterministic frame-index function. Never independently round duration and start, as that creates one-frame gaps or overlaps at touching boundaries. Keep spoken audio and ASR times unchanged. Check every decoded frame in a fractional-boundary render.

Razgon export must accept untouched code blocks saved by the former Python banker-rounding rule. Canonicalize only exact old/current endpoints from the matching project, script, audio and FPS in the export snapshot. Keep the real-move check strict; never use a blanket one-frame tolerance or alter rendered media. Test both the engine manifest and an actual exported seam before changing this compatibility path.

The final composition may extend by one output frame to cover a fractional audio end. Keep interior edit boundaries and speech timestamps unchanged; never introduce an empty rounding frame at the end. Exported circular and rounded masks must retain antialiased edges at their final size.

Keep preview media DOM nodes keyed by clip/source. Removing an outgoing transition clip must not reload the incoming image or video. Preload upcoming media and its source offset. CSS stacking values must be integers; graphic covers sit above scene media and below permanent branding. Test transition application, moving an existing transition, invalid drops, hover previews, and both sides of the final frame in the real browser.

Transition favorites are local editor preferences. A cut is the default absence of a join and is omitted from the library. Applied joins can be removed with their context menu. Visual effects share one preset definition between preview and export, must be reversible, and must not alter source media or voice audio.

Use cached small thumbnails and lazy image loading in the library. Do not load source-sized review sheets or every original video just to draw library cards.

Prefer the Studio's local script or HTTP API for plan creation, regeneration, and other supported production operations to save time and tokens. Verify plans through code/API/JSON and return plan_url for the user to review. The agent's browser remains available when useful, including for visual verification and operations the API does not support.

The scene planner belongs to this Studio. Keep the planning implementation in `backend/planner.py` and execute it through `store.generate_project_plan`. Read the channel's saved settings at execution time. A project's older settings snapshot and client-supplied settings cannot replace them.

`tools/video_plan.py` is a compatibility HTTP client. Keep it free of planning logic and local fallback generation. Channel settings are edited in Studio; the former standalone settings editor is retired.

Store each generated plan's settings snapshot, settings signature, generator identity and script hash. Show a stale-plan notice when saved channel settings have changed. Preserve the project identity, existing montage and previous plan when regenerating.

Ignore retired `opening_seconds`, `opening_clip_count` and `opening_clip_types` in new plans. ## Animated films: voice first, director frames, start production

A new episode opens on the plan with a voice drop zone and an optional voice text; without text the transcript becomes the script (`analysis_jobs.start(..., script=None)`). An animated channel never gets a plan split from the script alone: `generate_project_plan` without audio or timings calls `store.await_voice`, which keeps the script on the project as `voice_script` (shown in the voice text field and used by the recognition), moves a script-only draft to `plan-history`, refuses to replace a voice or director plan, and answers `awaiting_voice` (test: `test_animated_channel_waits_for_voice_instead_of_splitting_the_script`). The editor stays closed until the timeline holds a frame of the film (see «The plan page» below). A plan with `frame_source: razgon-direction` keeps its director's sentence groups through every rebuild (`planner.keep_director_frames`); changed sentences mark it `director_stale`. Such plans show «Почати створення ролика» instead of plan regeneration; the request (`POST /api/projects/<id>/production-request`) is stored on the project and kept in internal `backend/data/projects/<id>/production-request.json`. Speech comparison keeps script words with ASR time in `aligned_words`. Text fields have no focus ring. Restart or start the server only with `python3 tools/studio_restart.py` from this folder: it refuses while exports, speech, director, production, thumbnail or agent jobs run, and starts the server in its own session so it does not die with the agent's shell (on 30 October 2026 a server started with `nohup … &` from an agent session went down with that session).

Frames of an animated film are code until the author presses «Експорт MP4» (user, 30 October 2026): the frame agent (`backend/production.py`) writes the scenes and leaves «Кадр N» code blocks (`razgon_bridge.py slots --frames`), its run is done when `frame_progress.drawn` covers the requested frames and each is a block, and a frame drawn as code counts as made on the plan and the timeline; a request for frames already drawn is refused with 409. Agents the Studio starts run with `MULTIBOT_RENDER_ON_EXPORT=1`, so the bridge refuses `push` and `final` (its `sound` renders no picture and stays allowed); stopping a run (`director.kill`) also stops the commands Claude Code ran in their own process groups. A cancelled export kills its whole process group after `STOP_GRACE` seconds, even when the bridge is already gone. On a Mac the frames are rendered on the GPU and encoded on the hardware H.264 encoder (`render.mjs` defaults `--gl gpu` and `--encoder videotoolbox` on darwin; the bridge also passes `--gl gpu`): about 10 times faster than the software drawing with x264. The export's progress counts every frame of the film, with the frames already rendered from the same code done from the start. The export's project lock leaves the live preview (`/razgon-live`) free, and the page shows no banner for it. The thumbnail takes stills of code frames through `render.mjs --stills` (`thumbnail_gen.code_stills`). Tests: `test_production.py`, `test_director.py`, `test_export_control.py`, `tools/tests/test_razgon_bridge.py`.

A Razgon episode (`razgon-link.json` in Studio project storage) exports the same film as `tools/razgon_bridge.py push` + `final`: `backend/razgon_export.py` hands the bridge's `export` command each frame's rendered timeline clip, or null for a code block; the bridge renders those frames longest first, one Chromium worker each and as many at a time as keep the Mac's RAM under 90% (`razgon_bridge.RAM_LIMIT`; 80% until 19 November 2026, 88% until 26 November 2026, user: «дозволяю 90»; a young worker counted at 0.6 GB, `CHROMIUM_BYTES`, as one now holds about 0.3–0.5 GB; it was 2.2 GB when six at once froze a 16 GB Mac on 31 October 2026), reusing build/studio clips stamped with the same times and picture sources (`razgon_bridge.picture_fingerprints`, per frame since 1 November 2026: the frame's shots with their neighbours, the scene files that register them and its words, plus the shared config, assets, helper scenes and engine, by content; one changed scene re-renders only its frames), glues them with the channel plate and Razgon's −14 LUFS mix. A Razgon timeline with other clips, Studio transitions or effects (a mixed episode: photos, stock and text frames around some Razgon frames, as Alexey Gorbunov's) exports through the engine: first `razgon_bridge.py frames` renders only its code blocks (the same build/studio cache, each with a 0.5 s held tail for the transition out), then the engine draws each block from its clip (`razgon_export._mixed`, `app._render_razgon_blocks`). The live preview of a mixed episode draws only its `razgon_2d` frames (`frontend/razgon-live.js`). The live view says what went wrong over the preview instead of an empty frame (user, 2 November 2026: «всеодно сіре, хоча код є»): the kit's `live.html` posts `{razgon: 'error'}` for a scene that fails to load or throws, a page that never says «ready» after one fresh start reads «не відповідає», and «Перезапустити перегляд» stops this project's live server and starts it again (`razgon_live.start(pid, restart=True)`; a failed start names the last line of `build/live.log`). The plan page (`frontend/director.js`, `renderEpisode`) is one column, the same for photo and animated channels, with no
numbered steps: the voice stage as one line (file, length, «розпізнано, збіг N%» and the bin that starts the episode

ролика»: the film as a strip of its frames (on a photo channel each frame in its format's colour from
`planFormatVisuals`), the count picked by a drag across the strip (all frames by default), «Макс» and «Почати створення
ролика». The strip reads like a timeline: a tip over the frame under the pointer names its format, number and time;
pointing at a format in the legend lights its frames (a click keeps them lit); a pinch on the trackpad (ctrl + wheel,
Safari's gesture events) or − and + zoom it up to 40 times around the pointer, two fingers sideways move along it.

ролика». Every plan comes from the director after the voice, so the page has no plan regeneration.

`timing.audio.asset_id`): play and pause, a seek bar, the time and the volume (a mute button and a slider, remembered in the browser), inside the page; it stops when the page changes.

## Razgon follows the Studio's kit (31 October 2026)

The Razgon plugin with its studio kit lives in this repository (`razgon-plugin/…/make-2d-video/kit`), and Claude copies
the kit into `<YOUTUBE>/…/razgon-2d-studio` on first use. At every start the Studio brings each such copy up to date

from the working copy) and push to `main`. Tests: `tools/tests/test_razgon_sync.py`.

## A channel's video format and the export's quality (1 November 2026)

Each channel's settings hold «Формат відео»: the size (`video_size`: HD 1280×720, Full HD 1920×1080, 2K 2560×1440, 4K
3840×2160), the frame rate (`video_fps`: 24, 25, 30, 50, 60) and the quality the export window starts from
(`video_quality`: standard, high, max). A new episode takes the size and frame rate at creation (`store.create_project`);
a channel that chose nothing gets Full HD at 25 frames a second and the standard quality (the author's defaults).
They are not changed on an episode later: frame edges, transitions and Razgon's code frames are laid out at that rate.
The studio's global settings keep the channel root and export subfolder. The export window shows the episode's size and frame rate
and three bitrates with the file each makes (duration × (bitrate + 192 kbit/s audio)); the bitrates grow with the
picture (`store.video_bitrates`: 1/4/6 Mbit/s for HD, 2/8/12 for Full HD, 4/14/20 for 2K, 8/32/48 for 4K, half as much
again above 30 frames). `POST /export` takes `video_bitrate` (only those three), the manifest carries it, the GPU path
encodes with it and keys its cache on it, the CPU path uses it for VideoToolbox and x264 (`render.video_bitrate`). The

## Golden export: text edges, bitrate, motion-code text and instant CapCut previews (26 November 2026)

The user: «щоб експорт в мене був золотий… Чому текст рваний… контрастність… шаблонність… переходи в прев'ю, щоб моментально». Four fixes, each measured.

Jagged letters of motion-code clips in the GPU export came from alpha, not from compression. `tools/motion_code_render.mjs` encodes straight RGBA through FFmpeg's `hevc_videotoolbox`, which labels the file premultiplied; AVFoundation trusts the label and Core Image read every soft edge pixel at full brightness, so letters got a ring of light dots (the cached render itself differs from the lossless still by at most 2/255 of alpha). FFmpeg's decoder, the CPU path, reads it as straight and was right. `engine/gpu_render.swift` (`SequentialVideo.straightAlpha`) premultiplies HEVC tracks that contain alpha; ProRes 4444 already comes out of AVFoundation premultiplied and is left alone. Test: `engine/tests/test_gpu_alpha_video.py` (edge error 190 without the fix, under 20 with it).

The default export quality is «Висока» (`store.DEFAULT_VIDEO_QUALITY`, 8 Mbit/s for Full HD); all channels were moved from «Стандартна». Against a 40 Mbit/s render, host frames at 2 Mbit/s were 38.7 dB on average and 27.4 dB at worst, at 8 Mbit/s 42.7 and 30.9; dark animation scenes stay under the target either way. The export window and the channel settings no longer offer «Стандартна» (user: «2 біт убери з рендера»): «Висока» and «Найвища» only; a channel or card export that still says standard renders at «Висока».

`backend/motion_text_check.py P [--clips K034] [--json F]` measures the text of every motion-code clip against what lies under it in the export: the clip's runtime lists each line with its box, colour and shadow (`motion_code_render.mjs --text-scan`), draws the chosen moments with and without its letters (`--text-pairs`), the export renderer draws the film there without that clip, and WCAG contrast is taken against the 25th and 75th luminance percentiles with Razgon's thresholds (2.6:1, 3.5:1 under 40 px, shadow 0.4). It also counts text colours over all clips: one accent everywhere is the channel's template. The runtime's check parts are marked `check:start … check:end` and left out of the render cache key (`motion_code.CHECK_PART`), so the check never makes the export re-render motion code.

`GET /api/projects/<id>/capcut-ready` also returns `urls` {join id: film} of seams drawn from frames that are unchanged since (`app.capcut_sides`); the editor fills its previews from them at once, with no request a seam and no wait. The list is kept in the project's `capcut/ready.json` and read after a restart; a film whose file is gone is not taken. Test: `backend/tests/test_capcut.py` (`CapcutReadyFilmTest`).

Smooth motion is the studio's standard (user, 26 November 2026: «рух тексту… дрожанням… стандарт був в студії лише плавний рух»). Chromium's `fillText` puts letters on whole pixels: measured, text moving 0.1 px a frame held still and jumped a pixel, and wobbled sideways, while a picture drawn with `drawImage` glided. The motion-code runtime (`frontend/motion-code.js`, `smoothText`) draws each line once at a whole pixel into a cached bitmap (at the next quarter of scale when the line is scaled) and lays it at its exact fractional place: a still line is pixel for pixel what `fillText` drew, a moving one glides, in the preview and the export alike. Gradient or pattern fills keep the native text.

A frame where nothing moves the picture (no video, no Razgon block, no preset, no layer whose keyframes change place or size) gets a slow camera on all its layers together (`live_montage.stands_still`, op `frame_camera` with no frames), so a photo, its motion code and accents move as one; frame 71 of Astrofizika, a photo under motion code, stood still. `production.film_sounds` runs it after every film's frames are made.

## No dead text frames, honest transition sides, a shorter dissolve (27 November 2026)

The user, Astéroïde 37 and 86: «текстовий кадр появився, і там на протязі секунди просто пусто… це вважається вже… як брак… треба при створенні вже створювати так, щоб такого не було». A frame is dead when, once the transition into it is over, nothing comes on or visibly moves for more than `montage_ops.LEAD_GAP` (0.7 s): a background, a veil and a CapCut texture alone do not count. What comes in under the transition, or in its first `SETTLE` (0.2 s) after it, reads as standing there all along («воно появилося одразу після переходу… як будто воно там було»), so a director's graphic starts after that and comes in visibly (grows, slides), not only by a fade. ## Rules carried over from the agent's own memory (27 November 2026)

### Studio-wide

- **Automatic export.** With a channel's «Автоекспорт» on, `auto_pipeline` exports within a minute any frame run whose `production-request.json` reads done with `quality.passed` not false, and with «Автопублікація» on that export goes to YouTube by itself. Користувач: «рух не може бути рваний, перелітати на багато пікселів», «надпис не прив'язаний», «нащо там виділення пунктиром», «в майбутньому так не має робити створення кадрів».

`motion_direction.SMOOTH_CODE` додано до брифу агента кадрів (анімаційного й універсального) і до обох брифів правок. Його вимоги:
- фон-картинка на весь кадр із власним ґрунтом є одна площина на глибині 1 разом з усім, що на ній стоїть; паралакс лише між окремо намальованими шарами («тдс плаває», «чому я маю повторяти по 300 раз»: набір ролика ставив такий фон на 0,6, і все на ґрунті ковзало);
- позиції неперервні, без прив'язки до точок, що перескакують; написане чи намальоване героєм після дії видно цілим («букву C закрив космонавт»);
- кожна поза починається там, де закінчилась попередня;
- погойдування задаються гладкими функціями;
- частинки стартують у момент події;
- підпис малюється всередині `layer(g, cam, глибина, …)` того, що він називає (людина на ґрунті: шар ґрунту, глибина 1; гори й небо: шар фону) і стає частиною шару («надпис не прикріплений до землі чому») (користувач того ж дня: «чого надпис плаває, а не прикріплений до фону?», «навчись прикріпляти типу шари»). Окремо пораховані екранні координати теж ковзали: текст не масштабувався разом із горами;
- Земля, планети й зорі лежать у шарі неба фону (тій самій глибині), у чистому небі над хребтом («і планета на горах шар чому»);
- виділення тільки на самому об'єкті й лише за потреби, без декоративних пунктирних кіл;
- рухи камери стикуються без пауз;
- кожну зміну пози перевіряти стоп-кадрами з кроком 0,1 с.

Те саме записано в `render-qc.md` набору Razgon. Кадр 1 цього ролика переписано за цими правилами. Тест: `test_frame_briefs_ask_for_smooth_code_motion`.

## Перевірка стрибків у кадрах-коді, 27 листопада 2026 року

Користувач про кадр 1 Карла: «анимация рух не може бути рваний перелитати на багато пикселив… плавно мае бути все». `node render.mjs --project P --jump-check [--from A --to B]` малює кожен кадр відео й падає на картинці, фігурі чи рядку тексту, що за один кадр перелетів більше ніж на 22 px (при 1080), коли кадром раніше майже стояв, на стрибку розміру понад 12% і на позі героя, що почалась далі ніж за 40 px від попередньої (`build/jump_check.json`). Безкоштовна, близько 3 с на 18-секундний кадр. Агент кадрів отримує її поруч з logic-check і text-check (`montage_context.commands`). Перевірено на копії проєкту зі штучним телепортом і перескоком пози: обидва знайдено.

## Хештеги: від 1 до 9, строго одне слово, 27 листопада 2026 року

Користувач: «хештеги в метаданих мусять бути 1 словом. строго 1 слово», потім уточнення «від 1 до 9». Бриф метаданих (`episode_metadata.METADATA_RULES`) просить 1–9 хештегів, кожен одне справжнє слово без склеювання. `validate` приймає від 1 до 9 хештегів лише з літер і цифр (`#[^\W_]{2,30}`). Склеєні слова код не розпізнає, тож це тримає бриф. Тест: `test_hashtags_are_one_to_nine_single_words`.

## Підпис музики в описі лише за потреби, 27 листопада 2026 року

Користувач: «рандомно — якщо не треба вказувати, то можна не вказувати». `tools/youtube_publish.py music_credits` завжди називає трек, ліцензія якого вимагає вказати автора. Трек «без зазначення автора» він називає приблизно в половині роликів, і вибір для одного ролика сталий (`random.Random(pid)`). Це уточнює «обов'язково позначати в описанні» з розділу про музичну бібліотеку. Музична бібліотека лежить у публічному репозиторії `aloaloalo2/videokey-music-library`, з ліцензією кожного трека в README. Студія докачує її на кожен Mac при старті (`backend/music_sync.py`), нові треки туди викладає `tools/music_publish.py`. Тести: `tools/tests/test_youtube_claim.py` (`OptionalCreditsTest`), `backend/tests/test_music_sync.py`.

## Своя форма кожного опису, 27 листопада 2026 року

Користувач: «так само додавати треба рандомно то так то ні емодзі», «шаблонність хочу прибрати, щоб кожен опис був унікальний». `episode_metadata.shape(pid)` навмання вибирає для ролика форму опису:
- без емодзі, одне або два;
- від двох до чотирьох речень («2-4», уточнення того ж дня);
- заклик підписатися приблизно в 40% описів («інколи просити підписатись додатково»);
- один із шести способів почати (факт, питання глядача, головна помилка, сам предмет, сцена, що глядач зможе після перегляду);
- точну кількість хештегів від 1 до 9.

`prompt` додає цю форму до брифу метаданих. Для одного ролика форма та сама при повторному запиті (`random.Random(pid)`). Список останніх описів каналу, від яких новий має відрізнятися, лишається. Тест: `test_every_film_gets_its_own_description_shape`.

Того ж дня користувач уточнив: «опис має бути завжди від автора написаний каналу, від нього звернення, типу він писав цей опис, і дуже прямим текстом без води». Бриф метаданих (`episode_metadata.PROMPT`, `shape`) просить опис від першої особи автора каналу з прямим зверненням до глядача («я», «мы», «вы»). Текст прямий, кожне речення несе конкретику з ролика, без розгону й води. Вигаданих особистих історій немає: перша особа говорить лише про цей ролик.
